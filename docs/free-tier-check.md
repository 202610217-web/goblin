# 무료 한도 점검 (8단계)

Cloudflare Workers **무료 플랜**에서 이 게임이 하루에 몇 판까지 가능한지 계산한 기록입니다.
수치는 직접 잰 값이고(4명 봇이 3분 동안 실제처럼 플레이 → 30분으로 환산), 계산 규칙은 Cloudflare 공식 요금 문서 기준입니다.

## 무료 플랜 하루 한도 (Durable Objects)

| 항목 | 하루 한도 | 무엇이 여기에 들어가나 |
|---|---|---|
| 요청 | 100,000 | 들어오는 WebSocket 메시지 20개 = 1, 알람 실행 1번 = 1, 접속 1번 = 1 |
| 실행 시간 | 13,000 GB-s | 방이 깨어 있는 시간 × 128MB |
| 쓴 행 수 (SQLite) | 100,000 | `storage.put` 1번 = 1, `setAlarm` 1번 = 1 |

- 나가는 메시지(서버 → 화면)는 무료입니다.
- 한도를 넘으면 돈이 나가지 않고, 그날(UTC 0시까지) 해당 작업이 실패합니다.

## 4명 30분 한 판 예상 사용량

봇 행동: 방향 바꾸기 초당 1.5번(조이스틱 + 카메라 회전), 타격 2.5초에 1번, 점프 6초에 1번,
집 작업/치유 시도, ping 15초마다, 실제 타이머로 라운드 진행.

| 항목 | 8단계 전 | 8단계 후 |
|---|---|---|
| 들어온 메시지 | 15,762개 | 15,762개 |
| ping 메시지 (자동 응답) | 435개 | 435개 |
| → 메시지 요청 (÷20) | 810 | 810 |
| 알람 실행 요청 | 40 | 356 |
| 접속 요청 | 4 | 4 |
| **요청 합계** | **약 860** | **약 1,170** |
| **쓴 행 수** | **약 5,700** | **약 1,100** |
| 실행 시간 | 약 230 GB-s | 약 230 GB-s |

ping은 자동 응답이라 서버를 깨우지 않습니다(실행 시간 0). 요청 수에서 빠지는지는 문서에 분명히 나와 있지 않아서 **넉넉하게 포함**해 계산했습니다(30분에 약 22요청).

### 하루에 가능한 판 수 (4명 × 30분 기준)

| 한도 | 8단계 전 | 8단계 후 |
|---|---|---|
| 요청 100,000 | 약 116판 | 약 85판 |
| 쓴 행 100,000 | **약 17판** ← 가장 빠듯 | 약 90판 |
| 실행 시간 13,000 GB-s | 약 56판 | **약 56판** ← 가장 빠듯 |

→ 고친 뒤에는 **하루 약 56판(약 28시간 분량)** 까지 무료입니다. 친구들끼리 노는 용도로는 충분합니다.

재접속은 1번에 요청 1~2개(접속 + 입장 메시지)라 거의 영향이 없습니다.

## 8단계에서 고친 것

1. **같은 알람을 다시 걸지 않기**: 알람 시각이 바뀔 때만 `setAlarm` (전에는 30분에 약 2,500번 → 약 700번).
2. **자주 바뀌는 상태는 5초마다 모아서 저장** (`STATE_FLUSH_MS`): 이동, 체력, 작업/치유 시작·중단.
   단계 전환, 입장, 퇴장, 재접속 대기 시작은 바로 저장합니다.
   Durable Object는 10초쯤 조용해야 잠들기 때문에, 잠들기 전에 항상 저장됩니다.

## 점검 결과

- **Hibernation**: `ctx.acceptWebSocket` + `webSocketMessage/Close/Error` 핸들러 사용, `ws.accept()` 없음.
  ping은 `setWebSocketAutoResponse`로 응답하고, 실제로 ping 44개를 보냈을 때 서버 메시지 처리기는 한 번도 실행되지 않았습니다.
- **타이머**: 서버 코드에 `setTimeout`/`setInterval` 없음. 모든 마감(단계 종료, 작업 완료, 사망, 치유 완료, 재접속 마감, 모아서 저장)은 알람 1개로 처리합니다.
- **레이트 리밋**(연결별): 전체 메시지 초당 10개, 이동 초당 5개, 점프 초당 3개, 타격은 쿨다운 1초. 넘치면 버리고 오류를 보냅니다 (자동 테스트로 확인).
- **SQLite Durable Object**: `wrangler.toml`의 `new_sqlite_classes`.

## 모바일 점검

| 점검 | 결과 |
|---|---|
| 터치 이벤트 중복 전송 | 없음. 점프 1번 탭 → `jump` 1개, 행동 1번 꾹 → `hold_start` 1개 + `hold_stop` 1개 (서버 카운터로 확인). 포인터 이벤트만 쓰고, 버튼마다 처음 잡은 손가락만 추적 |
| 손가락이 버튼 밖으로 미끄러짐 | 누른 상태 유지(포인터 캡처), 그 손가락을 뗄 때만 중단 |
| 조이스틱 + 버튼 동시 사용 | 서로 방해 없음 (조이스틱을 민 채 꾹 누르면 제자리 고정, 버튼만 떼면 바로 중단) |
| 백그라운드 전환 | 즉시 이동 정지 + 작업/치유 중단 메시지. 돌아오면 끊겨 있으면 바로 재접속 |
| 입력 지연 | 내 캐릭터는 누르는 순간 화면에서 바로 움직임(예측). 서버로 가는 이동 메시지만 최대 0.2초 간격 |

### 더 개선할 수 있는 점 (지금은 하지 않음)

- 실행 시간이 가장 빠듯한 한도입니다. 하루 56판보다 많이 하려면 유료 플랜이 필요합니다(이동 메시지를 줄여도 방이 깨어 있는 시간은 거의 그대로).
- 서버 시계 추정은 "가장 빨리 도착한 메시지" 기준이라, 기기 시계가 게임 중에 크게 바뀌면 남은 시간이 잠깐 어긋날 수 있습니다.
- iPhone Safari는 전체 화면 기능이 없어서 "홈 화면에 추가" 안내로 대신합니다.

## 다시 재는 방법 (개발용)

서버를 `DEBUG_COMMANDS=true`로 실행한 뒤 `debug_stats` 메시지를 보내면 그 방의 카운터(메시지 종류별 개수, 저장 횟수, 알람 설정/실행 횟수, 접속 수)를 돌려줍니다.
