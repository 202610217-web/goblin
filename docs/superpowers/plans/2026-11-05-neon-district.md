# NEON DISTRICT + A/B 사이트 계획

## STEP 1. 기존 프로젝트 분석 (코드 기준)

| 항목 | 지금 구조 |
|---|---|
| 엔진/렌더링 | 자체 엔진. 화면은 Three.js(WebGL) + HTML HUD, 빌드는 Vite/TypeScript |
| 맵 크기 | 48m × 28m (`shared/world.ts` `PHYS.MAP_X/MAP_Y`) |
| 좌표 | x = 동, y = 북, z = 위, 단위 m. Three.js에는 (x, z, -y)로 변환 |
| 이동/카메라 | `shared/sim.ts` 결정적 물리(60Hz 고정 간격, 32방향, 속도 6m/s, 점프, 0.45m 턱 자동 오르기). 서버와 화면이 같은 함수로 계산. 3인칭 어깨 카메라(`shared/aim.ts`, `world3d.ts`) |
| 충돌 | 축 정렬 상자 목록 `BOXES` (벽/상자/계단/단상/집). 캐릭터는 0.8m × 1.8m 기둥. 맵 밖은 좌표 고정(clamp) |
| 집/파괴 | 체력 수치가 아니라 "꾹 누르기 작업" 진행률(`server/src/work.ts`): 혼자 30초에 부수기 완료, 손을 떼면 50% 체크포인트 규칙. 부수면 REPAIR(수리 1분) 단계 |
| 스폰 | 팀(A/B) 기준 고정 좌표 `SPAWNS`, 라운드 시작(COUNTDOWN)마다 그 자리로 |
| 동기화 | 서버 권위. 클라이언트는 이동 의도/행동만 보내고, 서버가 `room_state`, `move`, `work`, `swing`, `shot`을 방송. 화면은 같은 물리로 예측 후 서버 값으로 보정 |
| 서버/클라이언트 | 서버: Cloudflare Durable Object `GameRoom`(`server/src/room.ts`). 같은 코드가 "내 기기로 방 만들기"에서 브라우저 Worker로도 돈다(`client/src/host`). 클라이언트: 입력·예측·그리기만 |
| 맵 선택/로딩 | 없음. 맵은 모듈 상수 1개 |
| 단계 | LOBBY → CLASS_SELECT(5초) → COUNTDOWN(10초, 이동 불가) → ATTACK(2분) → REPAIR(1분) → ROUND_END(5초), 공격 3라운드마다 공수 교대, 6점 선승·듀스 |

## 결정

- **두 맵을 한 좌표 공간에 따로 둔다.** 기본 맵은 x 0~48, NEON DISTRICT는 x 60~156(96m × 56m, 가로·세로 2배, 면적 4배). 위치로 어느 맵인지 알 수 있어서 물리/조준/화살/카메라 함수의 시그니처를 바꾸지 않아도 된다. 물리는 그 맵의 상자만 본다.
  (전역 "현재 맵" 변수는 Cloudflare에서 방 여러 개가 한 프로세스를 나눠 쓸 수 있어서 쓰지 않는다)
- **맵 데이터 = 2m 칸 격자 하나** (`shared/neon.ts`). 이 격자에서 충돌 상자, 결계, 화면 메시, 미니맵, 더미 길 찾기를 모두 만든다 → 보이는 것·충돌·미니맵이 항상 일치.
- **결계는 몸 상태(Body)에 들어간다**: `bu`(결계 해제 서버 시각), `br`(공격/수비). 물리가 시각 `t < bu`일 때만 결계를 벽으로 본다 → 서버와 모든 화면이 같은 서버 시각에 동시에 해제.
- **NEON 규칙** (기본 맵은 원래 규칙 그대로):
  - 준비 시간(COUNTDOWN) 15초(`PREP_MS`) 동안 이동 가능, 결계 작동, 공격·작업 불가.
  - 스폰은 팀이 아니라 역할 기준(공격 스폰 = 서쪽, 수비 스폰 = 동쪽). 3라운드마다 공수 교대는 기존 그대로.
  - A/B 건물은 각자 작업 진행률(= 체력) 따로. 먼저 100%가 된 건물 하나로 즉시 공격팀 승리, REPAIR 없음. 같은 시각이어도 서버가 마감 시각 순서대로 하나만 처리.
  - 시간 초과 = 수비팀 승리, 공격팀 전멸 = 수비팀 승리 (기존 규칙).
- 기존 맵에는 A/B 사이트를 넣지 않는다: 집이 각 팀 스폰 바로 뒤에 있는 대칭 구조라 사이트 방식이 맞지 않음. 맵 선택은 로비에서 방장이 한다.

## 단계

2. `shared/neon.ts` 격자 + `world.ts` 맵 목록/경계, `sim.ts` 맵별 상자·경계 → 테스트: 크기 4배, 맵 밖 이탈 불가
3. 건물/통로/계단/경사로/실내 → 테스트: 격자 길 찾기로 모든 구역·사이트 연결, 물리로 벽 통과 불가
4. 공격/수비 스폰 → 테스트: 스폰 위치가 바닥, 서로 떨어짐
5. A/B 사이트 체력 → 테스트: 독립 진행, 하나 파괴 시 다른 쪽 불가
6. 준비 시간·결계 → 테스트: 공격팀 스폰 탈출 불가, 수비팀 두 사이트 도달 가능·공격 구역 진입 불가, 해제 후 통과
7. 라운드/승리 → 테스트: 파괴 시 공격 승, 시간 초과 시 수비 승
8. HUD/미니맵 (같은 격자에서 그림)
9. 로비 맵 선택
10. 브라우저 4명 접속(사람 2 + 더미 2, 사람 4) 실제 플레이 확인
